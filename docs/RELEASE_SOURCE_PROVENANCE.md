# Release Source Provenance

The Context Graph contract package separates three facts that must not be collapsed into one claim: package bytes are internally coherent, package attestations authenticate those bytes against a protected source commit, and a release consumer has independently admitted the resulting immutable release. A successful checksum or a JSON field containing a commit SHA is not source provenance by itself.

`cwl-context-release-source-manifest` consumes the exact `package-evidence-verification.json` produced by the release-evidence job. It accepts only the verified three-artifact wheel/source/SPDX set for one semantic version and binds that snapshot to the Context Graph repository, `refs/heads/main`, the exact 40-hex source commit, and the protected `supply-chain.yml` signer identity. The command emits `cwl-context-release-source-manifest/v1` with the exact artifact SHA-256 values and a SHA-256 identity for the complete verified package snapshot.

The generated manifest is deliberately **not** authoritative provenance on its own. On a protected `main` push, the supply-chain workflow first re-verifies the downloaded package bundle and its wheel/source provenance and SPDX attestations. Only after those checks pass does it generate the release-source manifest, attest the manifest itself with GitHub artifact attestations, and independently verify that attestation against the same repository, protected ref, source SHA, signer SHA/workflow, GitHub Actions OIDC issuer, hosted-runner policy, and SLSA provenance predicate. The manifest plus the machine-readable verification record are retained together under the exact source SHA.

Consumers such as Enterprise Architecture Core must fail closed on a mutable branch, pull-request head, self-asserted `release_commit_sha`, or an unattested manifest. A consumer may use the manifest only after authenticating the manifest attestation and matching the declared artifact digests, distribution version/tag, complete contract bundle, schema/profile/admission/conformance evidence, SBOM, and package identity to the immutable release it actually installs. Consumer-specific authorization remains in the consumer Anti-Corruption Layer; this repository does not acquire application, EA, quarantine, malware, workflow, catalog, or runtime truth by publishing provenance evidence.

The first immutable release remains blocked until the intended `main` integration/default branch is protected and authoritative in live GitHub governance, the solo-maintainer ruleset is satisfiable without synthetic approval or routine bypass, exact-head required checks execute successfully, and release publication binds the retained source-provenance evidence to the published package. Open PR artifacts are candidate evidence only.
